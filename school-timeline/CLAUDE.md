# Claude Code 개발 지침: 스쿨타임라인 MVP

> **WebMaker2 에서 바꾼 점 (2026-11-05)** — 이 폴더는 webmaker2 리포 규칙(리포 루트 CLAUDE.md · GUIDELINES.md)을 따른다.
> - Astro · Tailwind · Cloudflare Pages 대신 **빌드 없는 HTML/CSS/JS** 를 `node deploy.mjs school-timeline` 로 Cloudflare **Workers** 에 올리고 xim · xms 에 자동 연결한다.
> - 계산 로직은 `js/school-year.js`(순수 함수, JSDoc + `tsc --checkJs` 로 타입 검사), 일정 데이터는 `js/admission-2027.js`, 일정 파일은 `js/calendar-export.js`.
> - robots.txt · sitemap.xml 은 xms 가 만든다(메뉴 기준). 테스트 · 개발 도구는 `_dev/`(웹에 안 올라감). 자세한 건 README.md.

반드시 `PRD.md`를 먼저 읽고 그 내용을 소스 오브 트루스로 사용한다.

## 최우선 목표
한국어 모바일 우선 검색 유입형 학년·취학 안내 웹사이트를 구현하라. 개발 후 사용자는 생년월일을 입력하여 정확한 초·중·고 학사 타임라인을 계산하고, 2027년 초등 취학 공식 일정 및 체크리스트를 확인할 수 있어야 한다.

## 구현 규칙
- Astro + TypeScript + Tailwind CSS + Vitest + Playwright를 사용하고, Cloudflare Pages의 정적 사이트로 빌드한다. 프로젝트에서 확인한 최신 패키지 API에 맞춰 설치한다. 프레임워크 추가는 필수 기능에 필요한 경우만.
- DB, 인증, 유료 API, 사용자 추적, 임의의 AI 계산은 추가하지 않는다.
- 모든 사용자 대상 UI·카피는 자연스러운 한국어. 정확한 한국어 맞춤법/날짜 표현 적용.
- 계산 로직은 `src/lib/schoolYear.ts` 순수 함수로 구현하고 UI에서 분리한다. 테스트 케이스는 PRD 9절을 기준으로 작성한다.
- 날짜는 로컬 YYYY-MM-DD 검증 함수로 처리하고 타임존으로 날짜가 하루 밀리지 않게 한다.
- 부모가 입력한 생년월일은 클라이언트에서만 다룬다. 서버·URL·로그·analytics에 남기지 않는다.
- 2027 취학 관련 데이터는 출처·검증 일자·법정기한/학교별 안내 구분을 함께 저장한다. 출처 검증 불가 내용을 사실로 단정하지 않는다.
- 계산 결과를 보기 위해 광고를 클릭하거나 로그인하도록 요구하지 않는다.
- 메타태그/robots/sitemap/canonical/OG 및 HTML 본문은 사전 렌더링한다. 자동 생성 SEO 도배 페이지 금지.
- 반응형 360px, 768px, 1280px에서 QA하며 WCAG 접근성 기본 구현.
- UI는 정갈한 교육 서비스: 폰트 Pretendard 사용 가능 시 적절하게 로드하되 외부 CDN 의존 없이 시스템 폰트 폴백 유지. 색상은 차분한 네이비·세이지 그린.
- 2028 내신 계산기, 키 계산기, MBTI, 실제 교육청 API 연동은 이번 버전에서 구현하지 않는다.

## 실행 방식
작업을 한 번에 뭉뚱그리지 말고 아래 마일스톤 순서로 수행한다. 각 단계에서 파일을 작성하고 스크립트 테스트를 실행하며 결과를 짧게 보고한다.
1. 프로젝트 초기화 / 패키지 / 빌드 / 공통 레이아웃 / 라우팅.
2. 학년 계산 엔진, 입력 검증, 단위 테스트.
3. 계산기 페이지, 결과 표, 타임라인, 모바일 뷰.
4. 2027 취학 안내, 법정 기한 데이터, 체크리스트, 프린트와 공식 일정 ICS.
5. 신뢰·SEO 페이지, robots, sitemap, 메타, 문의 링크.
6. 전체 테스트, 360px 모바일 QA, Cloudflare Pages 빌드 및 배포 README.

## 완료 기준
- `npm run build` 성공.
- `npm run test` 성공; 위에 지정된 날짜/입학/학년도 경계 테스트 통과.
- Playwright 주요 흐름 통과.
- 실제로 존재하지 않는 행사일을 만들지 않음.
- 입력이 없어도 Googlebot이 읽을 수 있는 정적 본문과 내비게이션을 보유.
- README에 설치/개발/테스트/배포/콘텐츠 갱신 절차를 서술.

막히면 적당히 추측해서 건너뛰지 말고 에러 원인과 대안을 기록한다. 기능을 줄일 경우 반드시 PRD와의 차이를 보고한다.
